# AILIS 多层用户理解：个人试用版

这是独立试验分支，不是正式版升级；不承诺已经证明长期体验提升。

## 安装与隔离

- 产品与快捷方式：**AILIS Memory Trial**；可与普通 AILIS 并存。
- 应用 ID：`com.ailis.desktop.memorytrial`；本地网关端口：19877。
- 用户目录：`%APPDATA%/ailis-memory-trial`。
- 对话、工作区、会话上下文、语音缓存、记忆均使用试用版目录。
- 按用户选择从空白开始，不复制普通版账号配置、旧对话或旧画像。首次使用需自行登录/配置模型。
- 普通版仍使用原目录。请不要在试用版设置中手动把状态目录改回普通版目录。

## 运行方式

1. 正常聊天/执行任务仍由同一个 AILIS Agent 完成。
2. 到达原有上下文 hard/stop 阈值后，沿用原有便携语义压缩。压缩时额外保留用户本人及关系线索，产出**摘要1（第0层）**。
3. 第0层摘要持久保存。各层累计达到与摘要1相同的压缩输入阈值后，由模型将同层完整节点归并到上一层，得到用户偏好1、用户偏好2等。
4. 上层节点取代它覆盖的下层节点进入活跃集合；被覆盖节点保留在本地归档，不重复注入。每轮上下文使用这个集合的预算预览，不把预览冒充完整的新总结。
5. 高层归并使用用户定稿的中文提示词原文。关系包含在自然语言用户理解里，不运行旧结构化画像写入器和数值好感度判断。

从 `1.4.7-memory.2` 起，各层归并输入阈值以摘要1为准：没有实际会话预算时，沿用会话默认512000窗口×90%的hard阈值，即460800个**估算**token；每次捕获真实摘要1时，同步该次实际hard阈值，模型/用户配置生效后不固定死在460800。此阈值持久保存，重启后仍使用；每一层都遵循同一阈值。

每轮注入预算与归并触发条件已分离：3000字符只控制本轮展示给模型的预览，不再提前归并，不再因字符上限跨层合并。预算预览优先呈现较新材料，超出时明确标记为截断预览；完整节点仍在归档及活跃集合中，不会被预览替换。这个小视图不等于模型每轮都看到了全部长期材料。

从 `1.4.7-memory.3` 起，单个归并结果不设字符上限，不要求缩到原文70%以内，也不向模型发送输出字符限额。归并请求不再额外指定8192个输出token，使用模型连接既有生成设置；接口仍可能有默认/硬token限制，120秒请求超时仍保留。因此“不设字符上限”不代表接口可以无限生成。

较长但正常完成的结果按完整正文保存（仍经过既有凭据脱敏），不会因为3000字符预览预算而裁切存档。空回答、调用失败、工具调用或明确未正常完成的结果仍不消耗源节点。归并至少需要两个同层节点，单个刚生成的大摘要不会连续压缩自己；一次后台检查仍最多6次归并。

上述阈值集中在 `electron/ailis-hierarchical-user-memory.cjs` 构造参数，可在后续试验中调整。本次不改变主 Agent 原有上下文压缩触发阈值、工具权限、工具参数和执行超时。

**空白开始且尚未发生首次会话压缩时，长期分层记忆为空，这是预期行为。**当前对话的正常会话上下文仍然可用。不要用“聊一两句后立刻出现画像”作为验收标准。

## 可查看的证据

在控制面板现有记忆区域查看会话摘要数、归并次数及待处理/错误状态。用户理解展示在原有用户记忆块中，不另做聊天界面。

文件位于 `%APPDATA%/ailis-memory-trial/.ailis-state/memory/hierarchy/`：

- `state.json`：当前不重叠的活跃节点、实际会话压缩阈值、本轮预算预览及截断标记、计数与最近错误。
- `nodes/*.json`：摘要与归并节点归档、子节点ID、覆盖时间、模型用量（上游提供时）。这些文件包含个人信息，应按私人聊天记录保管。
- 原有 `.ailis-state/audit.jsonl` 中的 `memory.hierarchy.*` 事件：产生摘要、归并、错误。

首次捕获摘要不额外调用模型。需要高层归并时会产生额外模型请求和费用，使用试用版当时配置的模型连接。

## 失败与限制

- 模型调用失败、空回答、工具调用或明确被截断的输出不消耗原节点；完整材料保留，下一次检查可重试。注入预览是单独的上下文预算投影，不因模型失败而消耗源材料。正文较长本身不是错误。
- 模型连接层保留上游提供的结束原因；明确标记为 token 用尽、过滤或其他未正常完成的回答不会写入长期记忆。上游完全不提供结束原因时，无法仅凭正文可靠识别所有半截回答。
- 启动约1分钟后检查待处理任务，平时每6小时检查；新对话或压缩后约2分钟防抖检查。高层归并不阻塞当前任务。
- 原始归档会增长；分层解决的是活跃模型上下文大小，不代表磁盘历史无限使用却不增长。
- 原生加密压缩没有可读摘要；本试验依赖当前默认的 portable 语义压缩。旧本地规则回退也不会伪装成已生成可读LLM摘要。
- 多层摘要会有信息损失；测试只能检查工程行为，不能证明对用户理解更准确，也不保证模型一定消除旧误解。
- “清空长期记忆”清除活跃分层视图并使在途归并失效；本地归档仍保留，不等于安全擦除全部磁盘历史。
- 安装包无发行者签名。Windows可能显示未知发行者；本次只制作Windows x64个人试用包，不代表其他平台已验收。

## 个人体验建议

按正常方式长期使用；留意是否需要反复说明背景、明确纠正后是否重犯、是否误用过时的亲密关系、是否突然主动提起无关隐私。无需为了评测而刻意迎合系统。

本分支未合并main，不发布到GitHub。停止试用时退出/卸载试用版即可回到普通AILIS；试用目录默认保留。
