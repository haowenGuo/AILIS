# AILIS v1.4.0 十人真实用户内测

## 目标

邀请 10 名真实用户在自己的 Windows 电脑上完成至少一条日常工作流。内测优先收集安装、理解上下文、工具执行、长任务恢复和语音体验问题，不把 Star 作为参与条件。

## 用户构成

| 用户类型 | 人数 | 建议任务 |
| --- | ---: | --- |
| 开发者 | 3 | 阅读项目、定位问题、修改或运行代码 |
| 内容与研究工作者 | 2 | 搜索资料、整理来源、生成结构化结果 |
| 办公用户 | 2 | 读取文件、整理表格、撰写邮件或摘要 |
| AI Agent 使用者 | 2 | 长任务、失败恢复、与其他 Agent 对照 |
| 普通桌面用户 | 1 | 安装、语音对话、记忆与日常问答 |

## 邀请文案

> 我正在测试 AILIS v1.4.0，一个有 3D 角色、语音和长期记忆，也能执行真实桌面任务的开源 AI 伙伴。想邀请你在自己的 Windows 电脑上试一条真实工作流，不需要给好评，也不要求 Star。我更需要知道哪里难装、哪里看不懂、哪里做错或卡住。完整过程约 20 到 40 分钟；日志和录屏都可以先脱敏，是否提供录屏完全由你决定。

## 每位用户的最小流程

1. 从 GitHub Latest Release 下载安装版或便携版。
2. 完成首次启动和模型配置。
3. 自选一条平时确实会做的任务，不使用项目提供的标准答案。
4. 记录任务是否完成、耗时、人工介入次数和最明显的问题。
5. 在愿意的情况下提供脱敏日志、截图或录屏。
6. 通过 GitHub Issue 提交反馈，或由项目维护者代为整理成匿名 Issue。

## 反馈字段

- Windows 版本与硬件概况。
- 安装版或便携版。
- 任务原文与预期结果。
- 实际结果：成功、部分成功、失败、卡住。
- 总耗时与人工纠正次数。
- 是否使用语音、屏幕上下文、文件、网络或电脑操作。
- 最早出现问题的步骤。
- 可公开的脱敏日志、截图或录屏链接。
- 最希望下一版修复的一件事。

## 隐私与录屏

- 录屏不是参与条件。
- 提交前删除 API Key、账号、真实姓名、文件路径和敏感业务数据。
- 项目公开使用反馈内容前必须再次取得用户同意。
- 默认只公开问题和修复结论，不公开测试者身份。

## 完成标准

- 10/10 用户完成首次启动。
- 至少 8/10 完成一条真实任务。
- 所有失败都有明确阶段和可复现信息。
- 安装、协议、状态错配和基础设施问题优先于能力优化修复。
- 汇总时同时报告成功任务与失败任务，不筛选展示。
