# 运行观测与评估

AILIS 的运行事件、模型 usage、工具结果和工件构成分析一次任务的基础。Agent Lab 提供轮次视图；正式比较还需要固定实验条件和独立验收。

## 关联一次执行

至少保留程序路径、commit、dirty 状态、配置摘要、Session、run ID 和开始／结束时间。模型调用按 iteration 和调用标识关联，工具结果与调用一一对应。

Runner 发出 agent.token_usage，并保留决策与工具过程。Gateway 的分析接口组织时间线、轮次和成本；Lab 从这些接口读取记录。

## 指标

| 问题 | 测量 |
| --- | --- |
| 任务是否做成 | 验收通过数、有效完成数、计划任务数 |
| 模型用了多少上下文 | 去重后的原始输入与输出 token |
| 有多少输入被缓存 | 同口径缓存输入总量 / 输入总量 |
| 花了多少钱 | 各类调用的计费数量与对应单价 |
| 响应有多快 | 首个可见文本、最终可交付结果的时间 |
| 语音有多快 | 用户结束说话到首音频、播完的时间 |
| 工具是否可靠 | 成功、失败、超时、审批等待、协议异常的分布 |

同时报告样本量和未知项。时延可以给 p50、p95，但少量样本应直接列出观测值。

## Token 与成本

原始 provider usage 是计量依据。先确定输入是否包含缓存 token，再归一字段。单次调用可能同时出现在原始事件、轮次记录和聚合报告中，汇总时只能计一次。

若总输入包含缓存读取量，则未缓存输入为总输入减缓存输入。文字模型的简化成本为未缓存输入、缓存输入和输出各自乘单价。缓存写入、视觉、音频及工具服务按服务的计费项另列；压缩、重试和画像整理也需纳入范围。

原始字段缺失时标记 unknown，并报告 usage 覆盖率。当前某些汇总函数会填零，分析者应检查字段存在性，见[实现记录](../reference/implementation-status.md)。工具输出字节和内部预算近似值可描述数据规模，但不替代 provider token。

## 缓存分析

在同一 provider、模型和 Session 下比较连续请求，查看实际 instructions、工具 schema、输入顺序及前缀诊断。固定前缀是否复用、压缩是否替换历史、附件如何进入输入，会影响缓存行为。

缓存命中率、输入总量和最终成本应一起报告。减少输入量可能降低成本，即使缓存百分比没有升高；百分比升高也可能伴随总调用量增长。

## 质量与验收

根据任务制定可检查的完成条件：文件内容、测试结果、计算值、来源引用或实际界面状态。问答质量还包括正确理解请求、遵守偏好、解释限制和证据充分性。

模型 judge 可作为辅助评分，记录它的模型、提示和样本。工具 exit code、Agent 状态和业务验收分别记录。

比较两个版本时固定输入、工具、状态初始化、模型参数、并发、超时和重试规则。正式数据集使用对应官方验收规则，基础设施失败与答案错误分类保存。

## 分层验证

先运行离线单元与契约测试，再用受控模型和 scratch 验证执行链，最后进行获授权的真实小样本。扩大评测前确认 usage、结果、元数据和工件链完整。

原始记录可能包含私密输入或凭据。公开报告应提供脱敏摘要和可复核标识，而不是复制整份用户状态。
