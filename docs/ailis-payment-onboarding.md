# AILIS 微信与支付宝开通说明

申请要求核对日期：2026-09-19；部署状态更新：2026-09-20。当前申请人只有个人账号，尚未提供商户号或支付应用凭据。

## 先选择收款主体

AILIS 需要的闭环是：用户下单、扫码付款、平台通知服务器、服务器增加会员期限与额度。
个人转账收款码本身不能直接提供这里所需的商户订单与服务端通知接口。

| 情况 | 可以推进的事情 | 仍需解决的事情 |
| --- | --- | --- |
| 只有个人微信账号 | 查看商户接入要求、准备申请材料 | 当前直连 Native 路线需要符合条件的商户主体；个人钱包不能直接当商户 API 使用 |
| 只有个人支付宝账号 | 实名登录开放平台，查看自用应用和沙箱能力 | 应用创建与生产支付产品开通是两步；实际业务场景和资质仍需平台审核 |
| 个体工商户 | 按真实经营业务申请微信/支付宝商户与应用 | 营业执照、经营者身份证、结算账户、业务页面等材料，以产品申请页为准 |
| 经服务商接入小微商户 | 向具备权限的服务商核实支持的业务与结算条件 | 不是现有直连代码填个参数即可使用；还涉及子商户协议与接口 |

对于准备长期运营的 AILIS，建议先评估以个体工商户申请；并非一定要注册有限公司。
不要把“已有支付宝个人账号”理解为所有线上支付产品均已开通，也不能一概认定个人不能申请任何接口。
微信网站接入材料明确列出了个体工商户；支付宝允许个人商户入驻开发平台，但具体支付产品有各自条件。
参见 [微信网站接入指引](https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_website.shtml)、
[支付宝自用型开发者接入流程](https://open.alipay.com/platform/accessProcessPage.htm)。

## 按当前代码对应的产品申请

| 通道 | 代码已经实现的产品 | 对接前需要核实 |
| --- | --- | --- |
| 微信 | 普通商户 Native 支付，`/v3/pay/transactions/native` | 商户产品权限、与商户号绑定的 AppID、AILIS 实际经营类目 |
| 支付宝 | 扫码预下单，`alipay.trade.precreate` | 该产品是否接受 AILIS 的线上软件会员场景；若平台要求电脑网站支付，需改接 `alipay.trade.page.pay`，不能把线上业务申报成线下门店 |

官方入口：[微信支付商户平台](https://pay.weixin.qq.com/)、[支付宝开放平台](https://open.alipay.com/)。
申请说明应按实际情况描述“软件会员服务、包含使用额度、用户主动续费”，不要填写尚未实现的自动扣款。
主体实名、经营资料、结算账户确认与签约需要账号持有人办理；代码不能代替这些步骤。

## 开通后需要交给后端的配置

| 配置 | 来源/用途 |
| --- | --- |
| `APP_PUBLIC_BASE_URL` | 用户最终访问的 HTTPS 站点域名；拼接以下两个回调路径 |
| `APP_WECHAT_PAY_APP_ID` | 与商户号绑定的应用 AppID |
| `APP_WECHAT_PAY_MCH_ID` | 微信商户号 |
| `APP_WECHAT_PAY_SERIAL_NO` | 商户 API 证书序列号，用于请求签名身份 |
| `APP_WECHAT_PAY_PRIVATE_KEY_PATH` | 商户 API 私钥 `apiclient_key.pem` 在服务器上的位置 |
| `APP_WECHAT_PAY_API_V3_KEY` | 商户平台设置的 32 字节 APIv3 密钥，用于回调解密 |
| `APP_WECHAT_PAY_PLATFORM_SERIAL_NO` | 当前验签公钥的 ID，例如 `PUB_KEY_ID_...`；不要与商户 API 证书序列号混用 |
| `APP_WECHAT_PAY_PLATFORM_PUBLIC_KEY_PATH` | 微信支付公钥 PEM 文件位置；当前加载器接收公钥，不直接接收 X.509 证书文件 |
| `APP_ALIPAY_APP_ID` | 已创建的支付宝支付应用 AppID |
| `APP_ALIPAY_PRIVATE_KEY_PATH` | 应用 RSA2 私钥文件位置 |
| `APP_ALIPAY_PUBLIC_KEY_PATH` | 支付宝公钥文件位置；不是上传给支付宝的应用公钥 |
| `APP_MEMBERSHIP_PLANS_JSON` | 服务端价格和额度计划，尚待产品定价，不填写虚构的正式价格 |

回调路径为 `/api/payments/wechat/notify` 和 `/api/payments/alipay/notify`。
私钥只保存在服务器受限文件或服务环境中，不能进入前端、Git 或本说明。
微信公钥来自商户平台“账户中心 → API安全 → 微信支付公钥”；参见
[微信公钥与 ID 说明](https://pay.wechatpay.cn/doc/v3/merchant/4013038816)。
当前只配置一个微信验签公钥，尚无新旧平台证书并行轮换能力；已有商户处于证书/公钥混用阶段时，需先核实切换状态。

## 测试和上线

1. 本地使用临时密钥、隔离数据库、模拟 HTTP 传输验证签名与账本。运行：

   ```powershell
   python -m unittest tests.test_domestic_payment_protocol -v
   ```

2. 支付宝使用独立沙箱应用、沙箱公钥和沙箱网关。网关从当前沙箱控制台复制，不与正式凭据混用。
3. 微信 API v3 没有独立的支付沙箱；商户开通后，先核实签名配置，再通过明确的小额真实订单验收。
4. 核对下单、支付通知、重复通知只入账一次、金额不匹配不入账、会员续费保留剩余天数。
5. 实际收费启用前，完成 PostgreSQL 线上切换和账本验证，再打开支付及额度门禁。

微信 APIv3 的沙箱限制见 [官方安全实践](https://pay.wechatpay.cn/doc/v3/partner/4012082456)，
支付宝沙箱入口见 [开放平台支持中心](https://open.alipay.com/support/supportCenter.htm)。
本地模拟通过只能证明已覆盖的协议与账本行为，不能替代平台联调、商户审核或真实入账验证。

## 当前实现范围

- 当前是用户主动购买/续费：收到成功通知后立即增加该订单额度和 30 天会员期。
- 没有钱包签约、自动扣款、自动月度补额度；当前请只使用 30 天方案，不能把 `interval=year` 当作已实现的年卡。
- API 额度门禁目前按配置的单次请求额度扣减，还没有按模型实际输入/输出 Token 分类结算。
- 页面轮询查询的是 AILIS 本地订单；支付平台主动查单补偿、退款、对账尚未实现。
- 协议修复已于 2026-09-20 部署到 `150.109.13.189`；服务器隔离环境的 21 项支付、账户与 Relay 回归通过。微信、支付宝及会员/额度扣费开关仍关闭，未进行真实付款联调。见[部署记录](ailis-account-api-payment-audit-20260919.md#2026-09-20-部署记录)。

后续顺序：确认收款主体和支付产品 → 提供商户配置 → 平台联调 → 补齐查单补偿与退款对账 → 确定收费规则 → 正式开放。
