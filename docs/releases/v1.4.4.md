# AILIS v1.4.4: self-contained local ASR release

This release keeps the v1.4.3 execution baseline and the newer AILIS hosted-server
address, including the subsequently verified clean-workspace and error-preservation
repairs. The multiplatform packaging changes do not modify model instructions or
replace EXEC with another tool orchestration path.

## Intended downloads

| System | Architecture | Format | Native acceptance runner |
| --- | --- | --- | --- |
| Windows | x64 | Setup EXE, portable EXE | Windows Server 2025 |
| Linux | x64 | AppImage, DEB, tar.gz | Ubuntu 22.04 |
| macOS | Intel x64 | DMG, ZIP | macOS 15 Intel |
| macOS | Apple Silicon arm64 | DMG, ZIP | macOS 14 ARM |

The final Release must link a successful four-target workflow run. A configured
matrix is not evidence that its targets passed. See each uploaded native acceptance
report for actual OS, architecture, source commit, executable paths and results.

Windows 10/11 x64 and Ubuntu 22.04-compatible x64 desktop environments are the
intended end-user environments; not every OS revision, driver or CPU is tested.
The macOS packages declare macOS 14 or later. Windows/Linux ARM and 32-bit systems
are not included. Linux distributions need the usual Electron desktop libraries;
AppImage may additionally need FUSE or extraction according to the distribution.

## Fixed default installation

All packages include the desktop application, private CPython 3.12.10, native CPU
inference dependencies and the complete frozen OpenAI Whisper Small snapshot.
No system Python, pip, CUDA or first-run model download is needed for local ASR.
The Windows installer has no optional runtime component selection page.
Speech synthesis still uses the hosted Microsoft voice service and needs network
access. No local TTS model or CosyVoice is bundled. LLM connectivity still requires
a functioning hosted connection or the user's own direct API configuration.

The ASR model and dependencies make these packages substantially larger than the
former sub-200-MB application-only installers. Actual compressed sizes and SHA-256
checksums are in the per-platform release manifests, not an estimated table.

## Native build and acceptance

Run `node scripts/prepare-bundled-asr.mjs` on the target OS/architecture, then
`pnpm release:native` from a clean committed source tree. The preparer uses frozen
per-platform dependency locks and verifies official CPU-wheel and model hashes.
Windows/Linux/Apple Silicon use PyTorch 2.6 CPU; Intel macOS uses the available
PyTorch 2.2.2 Intel wheel with NumPy 1.26.4. Only the fixed hashed safetensors model
is shipped; this is not a facility to load arbitrary downloaded pickle checkpoints.

`pnpm release:native:verify` checks embedded version/source identity, all frozen
runtime hashes, packaged shell/PTY and EXEC contracts, apply_patch behavior and
real offline speech recognition. Mac ZIP and Linux tar payloads are extracted
to new paths containing spaces and non-ASCII characters. Windows additionally
undergoes actual NSIS installation, installed runtime tests, first launch,
portable launch and uninstall on its disposable CI runner.

Recognition tests use two public-purpose synthetic Mandarin clips and silence,
a fresh profile, system-only PATH and poisoned developer Python/model paths.
A Python audit hook rejects attempted network connections. This is a process-level
test guard, not an OS firewall. Transcription character errors are reported
separately from runtime readiness. The tests do not exercise a real microphone,
every language, desktop accessibility permissions or a paid model request.

## Signing and OS permissions

No Windows publisher certificate or Apple Developer ID/notarization is supplied
by this build. macOS applications use ad-hoc signatures, so Gatekeeper may require
explicit user approval; Windows may display SmartScreen warnings. Do not disable
system-wide security protections. Microphone and screen/accessibility permissions
must be granted by the user when the corresponding feature is requested.

Do not advertise these unsigned packages as universally zero-prompt installation,
and do not call GUI automation or all hardware combinations verified merely
because runtime acceptance passed.
