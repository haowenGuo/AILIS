**分数、模型调用、Token、缓存和时延分别呈现，不合成一个总分。**缓存率采用 `Σ缓存输入 / Σ输入`，不是逐题百分比的平均值，也不是理论前缀可复用率。下表 M = 1,000,000 Token，显示值经过四舍五入；精确整数见 [JSON](evaluation/20260907-snapshot.json)。

## Harness 优化：同题前后对照

下面是 9 月 3 日输出修复前与 9 月 4 日输出修复后，经双边有效性审计的 **84 道共同题**，不是与 Codex 的对比。

| 指标 · 相同 84 题 | 输出修复后 | 输出修复前 |
| :--- | ---: | ---: |
| 通过率 | **75.00%** | 59.52% |
| 通过题数 | **63 / 84** | 50 / 84 |
| 模型请求 | **3,854** | 4,816 |
| 结果变化 | **17 题改善，4 题退步** | 共同题净增 13 通过 |

模型请求减少约 20%，但输入 Token 增加约 32%，累计 Agent 时间仅降低约 1.9%。并发、时限与基础设施也有变化，不能将全部变化单独归因于取消裁剪。

### Terminal-Bench

- 运行：`ailis-terminal89-output-integrity-parallel20-luna-max-20260904-v1`。
- 源码：冻结 `07c1e85` 加七个工具输出完整性文件；9 月 5 日独立连接修复单题未混入。
- 配置：Luna Max；并发 20→10，后期恢复 3/1；外层 3000s，内层仍有原题预算。保留已有效的通过/失败，基础设施恢复另记，不能视为与官方同条件的干净 pass@1。
- 原始 progress 保持 65 通过 / 23 失败 / 1 未决。审计发现 `bn-fit-modify` 的 verifier 依赖下载遇到 TLS 错误、测试未启动，将其从能力分母排除，未修改原奖励或补记通过。
- `adaptive-rejection-sampler` 为执行链基础设施中断；`video-processing` 同时有能力超时和判分故障，按既有能力时限失败政策保留 0 并注明，不擅自改变恢复资格。
- Codex 官方存档为 0.144.1 / Luna Max / 89 × 5 次，包含 4 次 reward-hacking 取消资格。AILIS 未接受同等级独立审查，不宣称审核条件完全一致。
- 官方存档不是本地 445 次实跑轨迹，也不是实时榜单。独立本地 Codex 逐题证据覆盖 16 道不同题（9 月 7 题、8 月 10 道有效题，caffe 重叠）；其余 73 题的对应奖励与时延未知，不能补造配对结果。

- 源码：`659bf61` 加冻结的统一 Agent 工作区改动，另有运行中的预检修复记录；不是裸提交，也不是后来的 GitHub 整理分支认证。
