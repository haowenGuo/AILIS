Terminal-Bench 的全 89 题已确认通过比例是 **65 / 89 = 73.03%**，这是当前下限，不是把未决题补记成能力失败。GAIA 的 122 题是非随机的已完成子集，不能将 77.05% 标成完整 165 题成绩。两套评测都尚未得到所有题目的有效结论。

## Terminal-Bench：与 Codex 对照

AILIS 数据来自 `ailis-terminal89-output-integrity-parallel20-luna-max-20260904-v1`：冻结 `07c1e85` 加七个工具输出完整性文件。9 月 5 日独立连接修复单题没有并入这一全量批次。

| 条件 | AILIS 输出修复批次 | Codex 官方提交的本地存档 |
| --- | --- | --- |
| 模型与推理 | gpt-5.6-luna，Max | gpt-5.6-luna，Max |
| 题目与重复次数 | 89 题，保留有效通过/失败；基础设施恢复另记 | 89 题 × 5 次，共 445 trials |
| 得分 | 65 / 87 = 74.71%，2 题未决 | 337 / 445 = 75.73% ± 1.32% 标准误 |
| Agent 版本 | 上述冻结快照，不是当前所有本地改动 | Codex 0.144.1 |
| 并发与时限 | 20→10 并发，后期恢复 3/1；外层 3000s，内层仍有原题预算 | 不同日期与执行环境，不能视为同负载对照 |

这是运行结果对照，不是单变量 Harness A/B。Codex 官方汇总已扣除 4 次 reward-hacking 取消资格；本批 AILIS 没有同等级的独立审查，不能宣称审核条件完全相同。官方数据是历史存档，不是本页重新查询的实时排行榜。

### 资源与时延

AILIS 下表统计每题当前选定的尝试，共 89 次，包含已产生开销的两题未决；不包含全部废弃/恢复尝试。Codex 的 Token 总量是 445 次除以 5 的 **89 次等量折算**，不是挑选最好的一轮。

| 指标 | AILIS，选定 89 次 | Codex，89 次等量折算 |
| --- | ---: | ---: |
| 输入 Token | 266,935,258 | 283,318,157.4 |
| 缓存输入 Token | 255,692,288 | 275,313,423.4 |
| 未缓存输入 Token | 11,242,970 | 8,004,734.0 |
| 输出 Token | 2,343,869 | 2,125,781.0 |

两边时间字段均为 trial 开始到结束，不混用 worker 总时间和纯模型时间。观测到的 3.46 倍时间差还包含机器、并发、时限、准备/判分与基础设施影响，不能全部归因于 Harness。高缓存率也不保证低时延。

Codex 存档的 cost 字段为 445 次合计 $241.45，89 次等量为 $48.29；这不是核对过的发票。AILIS 缺少对应账单及历史结算单价，**不发布推算成实付的金额**。Token 是已报告用量，缺失 usage 不代表零费用。

### 评分修正与逐题证据

- 原始 progress 保持 `65 通过 / 23 失败 / 1 未决`。离线审计发现 `bn-fit-modify` 的 verifier 下载依赖发生 TLS 错误、测试未启动，因此公开能力统计改用 `65 / 87`；没有修改原奖励或补记通过。
- `adaptive-rejection-sampler` 为执行链基础设施中断；`video-processing` 同时有能力超时和判分故障，沿用已有能力时限失败保留政策并注明，不擅自赋予重跑资格。
- 本地原生 Codex 独立逐题证据覆盖 **16 道不同题**（9 月 7 题、8 月 10 道有效题，`caffe-cifar-10` 重叠）。官方 445 次存档没有逐题奖励/时延；其余 73 题的 Codex 胜负仍未知，不能补造完整配对表。
- [公开数据](evaluation/20260907-snapshot.json) 列出全部 89 题的 AILIS 状态、时间、请求数、Token 和现有本地 Codex 样本；公开摘要不包含原始工具输出、登录信息或附件。

### 与前版比较

输出修复前的 9 月 3 日批次与当前批次经双边审计后，共同有效 **84 题**：旧版 **50 / 84（59.52%）**，新版 **63 / 84（75.00%）**；17 题转通过、4 题转失败，净增 13 题。模型请求 4,816→3,854，但输入 Token 增加约 32%，累计 Agent 时间只降低约 1.9%。并发、时限和基础设施也有变化，不能把全部改善单独归因于取消裁剪。

## GAIA：与本地原生 Codex 的同 122 题对照

AILIS 数据来自 `ailis-gaia165-unified-luna-max-20260905-v1`，基于 `659bf61` 加冻结的统一 Agent 工作区改动；运行中的预检修复另有记录。不是裸 `659bf61`，也不是 GitHub 后续整理分支的认证成绩。三方逐题核对 UUID、题目、参考答案和难度，使用同一次离线答案复核。

| 系统 | 复核明确匹配 | 纯自动匹配 | 推理 / 时限 / 并发 |
| --- | ---: | ---: | --- |
| AILIS + Luna | **94 / 122 · 77.05%** | 76 / 122 · 62.30% | Max / 3000s / 10 |
| 原生 Codex + Luna | 82 / 122 · 67.21% | 81 / 122 · 66.39% | Medium / 600s / 4 |
| 原生 Codex + GPT-5.5 | 97 / 122 · 79.51% | 96 / 122 · 78.69% | Medium / 600s / 历史分批恢复 |

“复核明确匹配”包括从已保存答复中人工确认所问答案，不是只展示机器原评分，也没有新生成答案。AILIS 另 1 题格式等价、24 题不符、3 题有歧义，未加进 94；GPT-5.5 另 1 题语义等价也单列。复核比较答复与参考答案，没有逐一重新联网核验所有引用。AILIS 有 13 道明确匹配题用时超过 600s，因此不能从此表推导等预算下的优劣。

## 历史结果与复核方法

8 月 A6 GAIA `119 / 165（72.12%）`、A7 Terminal-Bench `60 / 89（67.42%）`，以及 ToolSandbox、LongMemEval、PersonaMem、LoCoMo 的既有结果仍保留在 [历史评测页](https://github.com/haowenGuo/AILIS/blob/659bf61f2b340d2313b3bae386704265c8d2bba2/docs/evaluation.zh-CN.md)。它们属于各自冻结源与旧评分协议，不冒充当前统一 Agent 的新成绩。

本页附带的 [JSON 摘要](evaluation/20260907-snapshot.json) 保存原报告/源码锁的相对标识、SHA-256、统计原数和逐题索引。原始长日志仍在本地；哈希用于识别证据，**不等于已经公开了全部可独立重跑材料**。更新文档不改题目、答案、官方 verifier、原始成绩或恢复资格。

计量与协议说明见[运行观测与评估](engineering/measurement.md)。加权缓存率始终为 `Σ缓存输入 / Σ输入`；不对逐题百分比求平均，不把前缀理论可复用率当成实际服务器缓存命中率。
