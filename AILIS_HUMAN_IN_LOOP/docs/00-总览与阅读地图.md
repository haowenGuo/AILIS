# 00｜总览与阅读地图

## 1. 一句话认识 AILIS

AILIS 是一个“具身 Persona + 唯一任务代理 + 工具运行时 + 多层记忆”的应用。
同一套核心能力可以通过 Electron 桌面、纯网页 + Hosted Runtime、以及可选
FastAPI 服务呈现。VRM 角色负责可见人格、动作、表情、语音与口型；TaskAgent
负责计划、工具调用、证据、恢复和任务完成。

## 5. 推荐的七个学习阶段

### 阶段 0：建立运行概念

先读本书、[代码架构书](01-代码架构书.md) 和原仓库 `README.zh-CN.md`，不急着
钻进 1 万行级大文件。

### 阶段 1：跟通一个普通对话

从输入框事件追到 `ChatTTSSystem.sendMessage()`，再到
`AILISDesktopChatService`、Gateway、Agent，最后追 Persona Surface、TTS 和 VRM
返回路径。把每个跨进程边界写在自己的笔记里。

### 阶段 2：跟通一个工具任务

选“读取一个文件”这种低风险任务。依次观察 tool search/contract、决策、
permission evaluation、执行、tool output、evidence ref、最终回复。

### 阶段 3：跟通一个需审批任务

选写文件或发送邮件，确认模型提出的是语义决策，而确定性代码只执行 schema、
路径、权限、预算、生命周期与审批边界。

### 阶段 4：跟通一次记忆写入与召回

区分 raw ledger 的可审计记录、curated Persona Memory、当前会话历史和任务上下文。
检查召回 query、预算裁剪、脱敏和写入时机。

### 阶段 5：跟通一次失败与恢复

人为制造工具缺失、超时或配置缺失，观察错误分类、Persona 安全表达、checkpoint、
续跑和终止条件。

### 阶段 6：做一个小改动并闭环

只改一项行为，先添加/调整测试，再构建、运行目标模式、重新生成学习副本并校验。

## 6. 阅读一个文件的固定模板

对每个重要文件回答：

1. 它运行在哪个进程/环境？
2. 谁创建它、谁调用它、它调用谁？
3. 输入 schema 和返回 schema 是什么？
4. 哪些状态只在内存，哪些会持久化？
5. 正常、取消、超时、审批、失败各走哪条路径？
6. 哪些内容能进入模型，哪些能给用户看？
7. 有什么测试固定了它的契约？
8. 修改它会影响桌面、网页、Hosted 还是全部？

逐行总入口见 [逐行讲解索引](../generated/line-by-line/INDEX.md)。

## 7. 不要混淆的四组概念

- Persona ≠ TaskAgent：前者是用户面对的 AILIS，后者是执行工作的一套系统代理。
- Raw Memory ≠ Prompt Memory：原始账本用于审计/重放，进入 prompt 的必须筛选、
  脱敏、预算化。
- Tool result ≠ Evidence：执行返回不自动等于证据；需要来源引用、可用性和充足性。
- Web UI ≠ Hosted Runtime：静态网页只负责界面；完整 Agent/Memory/Tool 能力位于
  服务器运行时，浏览器通过 API/SSE 访问。
